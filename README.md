# صندوق الاقتراحات

نسخة أولية متكاملة قابلة للتشغيل محلياً والنشر كـ Web App.

## محتويات المشروع
- `index.html`: واجهة الطالب لإرسال الرسائل ومتابعتها.
- `admin.html`: لوحة دخول وإدارة الرسائل.
- `assets/config.js`: إعدادات الاتصال العامة بمشروع Supabase.
- `assets/student.js`: منطق إرسال الرسائل والمتابعة.
- `assets/admin.js`: منطق لوحة الإدارة.
- `assets/styles.css`: التصميم المتجاوب.
- `database/schema.sql`: الجداول والدوال وسياسات RLS.

## 1) إنشاء مشروع Supabase
1. أنشئ مشروعاً جديداً في Supabase.
2. افتح SQL Editor.
3. انسخ محتوى `database/schema.sql` كاملاً ونفّذه.
4. من Project Settings > API انسخ Project URL و anon/public key.
5. ضع القيمتين في `assets/config.js`.
6. لا تستخدم `service_role` في الموقع أبداً.

## 2) إنشاء حسابات المسؤولين
1. افتح Authentication > Users في Supabase.
2. أنشئ حساباً لكل مسؤول بالبريد وكلمة مرور قوية.
3. انسخ UUID الخاص بكل مستخدم.
4. نفّذ في SQL Editor، مع استبدال القيم:
```sql
insert into public.profiles(id, display_name, role)
values
('UUID-OF-ADMIN', 'مدير النظام', 'admin'),
('UUID-OF-MANAGER', 'مسؤول الصندوق', 'manager'),
('UUID-OF-REVIEWER', 'مشرف الرسائل', 'reviewer');
```
الأدوار:
- `admin`: إدارة كاملة للحسابات وقراءة جميع الرسائل.
- `manager`: قراءة الرسائل وإدارتها وإحالتها.
- `reviewer`: قراءة الرسائل المسندة إليه فقط وإضافة الردود والملاحظات عليها.

ملاحظة: النسخة الحالية تعرض قائمة المسؤولين النشطين للإحالة. اجعل بيانات العرض مقتصرة على أسماء العمل المناسبة ولا تستخدم بيانات شخصية زائدة.

## 3) التشغيل
للتجربة، افتح المجلد عبر خادم محلي (مثل VS Code Live Server) أو انشره على GitHub Pages / Netlify / Vercel.
لا يُنصح بفتح الملفات مباشرة عبر `file://` لأن بعض المتصفحات تمنع سلوكيات معينة.

## 4) اختبار أساسي قبل الإطلاق
- أرسل اقتراحاً مجهولاً، وتأكد أن الاسم والصف لا يظهران كهوية.
- أرسل رسالة باسم، وتأكد أن الاسم يظهر للمسؤولين فقط.
- جرّب المتابعة برقم ورمز صحيحين ثم برمز خاطئ.
- جرّب دخول مسؤول غير نشط.
- جرّب حساب reviewer على رسالة غير مسندة إليه وتأكد من رفض الوصول.
- جرّب عدم تسجيل الدخول ثم فتح `admin.html`.
- تحقق أن ملاحظات الإدارة الداخلية لا تظهر في واجهة متابعة الطالب.

## 5) تنبيهات أمنية مهمة قبل الاستخدام الفعلي
هذه قاعدة انطلاق وليست شهادة تدقيق أمني. قبل إطلاقها لطلبة مدرسة:
- أضف CAPTCHA أو حماية مناسبة من الإرسال الآلي، وحدود معدل إرسال على مستوى الخادم/الحافة. لا تعتمد على تعطيل الزر في المتصفح.
- راجع إعدادات Auth وقيود كلمات المرور وسياسات الجلسات.
- فعّل HTTPS عند النشر.
- لا تجمع بيانات شخصية غير ضرورية، وضع سياسة احتفاظ وحذف واضحة.
- راجع آلية التعامل مع البلاغات الحساسة ومن يحق له الاطلاع عليها.
- راجع سجلات مزود الاستضافة؛ قد تحتوي على بيانات اتصال حتى إن لم يطلب النموذج الاسم.
- اختبر سياسات RLS من حسابات فعلية مختلفة قبل الاستخدام.
- لا تنشر بيانات أو مفاتيح إدارية في GitHub.
- أضف آلية استعادة كلمة المرور للمسؤولين قبل التشغيل الرسمي.

## 6) حدود هذه النسخة
- الإشعارات داخل لوحة الإدارة تظهر عند تحديث الصفحة أو الضغط على تحديث؛ التحديث الآني Realtime لم يُفعّل بعد.
- زر/ميزة حذف الرسائل غير متاحة عمداً في الواجهة.
- لا توجد حالياً صفحة لإدارة حسابات المسؤولين من داخل الموقع؛ تدار الحسابات من لوحة Supabase.
- رمز المتابعة يُعرض مرة واحدة عند الإرسال؛ إذا فقده الطالب فلا توجد آلية استرجاع في هذه النسخة.
